**Update (beets 2.7+):** beets now has a multi-valued `genres` field, written to files as separate genre tags; the old comma-separated values were migrated automatically, and whatlastgenre (upstream, installed editable from `~/code/music/whatlastgenre` by `setup.sh`) now fills the list. See the status section at the end; the original writeup follows.

Beets has a `genre` field, but it officially only supports one string value. One can, however, use it to store multiple genres separated by commas. I do this using the `whatlastgenre` plugin (source code locally at `~/code/music/whatlastgenre`, installed into the `beets` conda environment via `python setup.py install` from there).

The whatlastgenre program needs a configuration file in order to operate. Here's mine:

```
$ cat ~/.whatlastgenre/config
[wlg]
sources = discogs, lastfm
whitelist = 
tagsfile = 
id3v23sep = 

[genres]
love = 
hate = alternative, electronic, indie, pop, rock

[scores]
artist = 1.33
various = 0.66
splitup = 0.33
minimum = 0.10
src_discogs = 1.00
src_lastfm = 0.66
src_mbrainz = 0.66
src_redacted = 1.50

[discogs]
token = ...
secret = ...

[redacted]
username = 
password = 
session = 
```

(discogs credentials not shown here)

I don't remember whether I crafted this by hand, copied it from somewhere, or if it was autogenerated. In any case, I doubt I customized it very much if at all.

By default, it seems whatlastgenre includes the top four genres it gleans for a given track. It puts them into the single `genre` field separated by commas. This works to get the metadata into the beets DB, but it does not play nicely with other beets plugins; for example, running `beet mbsync <item-query>` wipes out the wlg plugin's computed multi-genre in favor of only one or even none. But `beets import -L <item-query>` restores the multi-genre.

I notice that Beets now has a first-party `lastgenre` plugin listed in its documentation, which requires the [`pylast`](https://pypi.org/project/pylast/) library. But this plugin only uses Last.fm / Libre.fm, whereas according to its README, whatlastgenre uses Discogs, Last.FM, MusicBrainz, Redacted.ch. (I haven't configured Redacted.ch, but I do have a Discogs account.) I'm not sure whether switching plugins here would be a good idea, or a distraction from solving the problems at hand.

So there are really two issues here:

1. Ensure I'm using the current best practices for managing genres with my Beets collection.

2. Make it easier to shuffle songs of particular genres when playing tracks e.g. on iBroadcast, by tagging tracks with [usertags](https://github.com/igordertigor/beets-usertag) corresponding to the genres they're associated with. Because iBroadcast's genre view is largely useless when a track is tagged with a comma-separated list of genres that it treats as a single genre string.

For (1), maybe I should switch plugins, or maybe not. Maybe there is a more modern way to store multiple genres as a list.

For (2), maybe I should be splitting the genre string when uploading tracks to iBroadcast so that it can be smarter about it. Or more likely, it has no way to label a track with multiple genres for use with its genres view, and I should strip off the secondary genres in favor of uploading only one. But it very likely gets the genres from the ID3 metadata, which means that I'd have to not write multiple genres into the genre field (`TCO`? `TCON`? What's the difference?). My current thinking is that it will be easier to simply add one usertag per genre for each track, which my beets-ibroadcast plugin already syncs with iBroadcast, so then I'll at least have tags there corresponding to the genres. I've been reluctant because I need to decide on a naming convention for tags so they don't overwhelm the existing non-genre tags there so badly... at least if they are all prefixed with e.g. `genre-` or `g-` or some such, they'd all be sorted together. (I don't think iBroadcast supports tag hierarchies, unfortunately.)

This issue is also trickier than might at first appear because "genre" is such a fuzzy concept. Some of them are super general, some are super specific. I don't want to have *all* super-specific genre tags on iBroadcast... maybe only the ones that have at least X songs in them? So it's a moving target.

See also:
* The `.local/genres-all.txt` and `.local/genres-ok.txt` files, which contain extracted genres from my collection, marking which ones I think are worth tagging. It's been years since I generated them, so don't remember how I did it, but I think my idea was to keep only the top X genres that aren't too general.
* The `.local/tag-genres.sh` script, which outputs another shell script for tagging all the tracks in my collection using `beet addtag` commands. I never ended up doing it though, because: A) `beet addtag` is super slow to run because it's working track by track with custom attributes, which are slower that regular attributes in beets; and B) I was nervous about actually having all these genre tags pooping up my otherwise very useful small curated set of tags I'm using now.

## Status (beets 2.14)

* Storage: solved by the `genres` list field (see top).
* mbsync: `musicbrainz.genres` is now `no`, so `beet mbsync` no longer
  replaces whatlastgenre's genres. (When MusicBrainz had no genres, beets
  already left existing ones alone: `overwrite_null` is empty by default.)
  The lowercase genres from earlier mbsyncs (`rock`) are normalized; see
  below.
* Cleanup (November 2026): 344 items and albums normalized to the
  library's capitalized spellings (`rock` → `Rock`, `HARDSTYLE` →
  `Hardstyle`, stray spaces). Synonyms merged (`Drum and Bass` → `Drum &
  Bass`, `newage` → `New Age`, `musicals` → `Musical`, `rock instrumental` →
  `Instrumental Rock`, `rock_pop` → `Rock` + `Pop`, Dutch/French
  `Alternative en Indie` → `Alternative` + `Indie`). Junk dropped (`genre`,
  `default`, `data`, DJ website URLs). Database only; not yet written to
  files. Still questionable: `Misc`/`Miscellaneous`, `canadian`,
  `Popular music`, and OC ReMix's franchise names as genres (`God of War`).
* lastgenre: much improved (multi-valued, whitelist with a genre tree,
  normalization, ignore list, `beet lastgenre --pretend`), but still
  Last.fm only. whatlastgenre also uses Discogs, and works, so no switch.
* iBroadcast tags: `tag-genres.sh` was partially run at some point. The
  `g-*` tags were already gone from iBroadcast; the local `g-*` usertags
  (1,074 items) are now removed too, so `beet ib-upload` won't recreate
  them. (The script also had a quoting bug: `R&B` produced the tag `g-r`.)
* iBroadcast genres: beets-ibroadcast doesn't send genres; iBroadcast reads
  them from the uploaded file. Its track data now has `genre` plus a
  `genres_additional` list, filled for some files (842 tracks), so it does
  support multiple genres. Most tracks show the whole comma-separated
  string as one genre (`Jazz, Trance, House, Soundtrack`, 1,379 tracks).
  Tested (2026-11-02): an MP3 written by beets 2.14 (one ID3v2.4 `TCON`
  frame with four values) shows on iBroadcast as the single genre
  `Rock/Alternative/Alternative Rock/Grunge`, with no `genres_additional`.
  So iBroadcast does not split ID3 multi-values. The tracks that do have
  `genres_additional` are mostly Ogg Vorbis and M4A files (833 of 842),
  which can hold several separate genre fields. Next: test one Ogg file
  with several `GENRE` fields.
